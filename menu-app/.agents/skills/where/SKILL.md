# 자료 위치 찾기

학생이 개념이나 오류 메시지를 대면 **어느 앱의 어느 파일을 봐야 하는지** 짚어 준다.

## 절차

1. **`REVIEW.md`를 먼저 본다.** 저장소 루트에 하나 있고, 네 앱을 모두 다룬다.

   | 절 | 범위 |
   |---|---|
   | `01_react-basics` | 가상 DOM, JSX, props, `useState`, `key`, 불변성 |
   | `02_api-viewer` | `useEffect`, fetch·axios, 로딩·에러·빈 결과, `useMemo` |
   | `03_list-detail` | react-router, `Link`, `useParams`, `useNavigate` |
   | `04_form-auth` | 제어 컴포넌트, form Actions, POST·PUT·DELETE, `useContext` |
   | `05_vibe_design` | **4일차** 디자인 시스템·토큰·CSS Modules |

   `REVIEW.md` 맨 아래의 **증상으로 찾기** 표가 가장 빠르다. 학생이 콘솔 오류를 붙여넣으면 그것으로 찾는다.

2. **앱을 좁힌 뒤에는 그 앱의 가이드(`*_GUIDE.md`)를 본다.** 학습 목표와 완성 확인 목록이 거기 있다.
   그다음 `starter/src/` 안의 파일을 직접 검색해 정확한 파일과 `TODO` 번호를 찾는다.
   **추측하지 않는다.** 파일을 열어 확인한 것만 말한다.

3. **이렇게 답한다.**

   > `apps/03_list-detail/starter/src/pages/DetailPage.jsx` 의 `TODO 4`
   > - 주소의 `:id`를 꺼내 그 값으로 상세를 불러오는 자리다.
   > `REVIEW.md`의 "03. useParams와 의존성 배열" 항목도 같이 보면 좋다.

4. 여러 곳에 흩어져 있으면 **가장 기본이 되는 곳 하나를 먼저** 짚고, 나머지는 목록으로만 준다.

## 학습 순서를 같이 알려준다

찾은 절 제목에 `[4일차]`가 붙어 있으면 그것도 말해 준다.

> 그건 4일차 바이브 디자인 자료야. 3일 안에는 안 봐도 되고, 지금 막힌 것과 관계있으면 봐도 돼.

앱 번호도 순서다. 앱 2를 하는 학생이 `useContext`를 물으면 앱 4에서 다룬다고 알려주고,
지금은 몰라도 된다고 말한다.

## 코드를 붙여넣지 않는다

**위치만 알려주고 내용은 학생이 직접 열어 보게 한다.**

`starter/`를 채우다가 물어보는 경우가 많다. 여기서 코드를 그대로 옮겨 오면
사실상 답을 주는 셈이 된다. 한 줄짜리 요약은 괜찮지만 코드 블록은 붙여넣지 않는다.

학생이 "그냥 코드 보여줘"라고 하면, 파일을 열어 보라고 안내하고
그래도 막히면 "힌트 줘"라고 말하면 된다고 알려준다.

## 못 찾았을 때

수업 자료에 없는 내용이면 **없다고 말한다.** 그럴듯한 파일명을 지어내지 않는다.

3일 자료에 없지만 React에 있는 것(`useReducer`, `useRef`, Next.js 등)이면
이 과정에서는 다루지 않는다고 말하고, 지금 만드는 앱에 필요한지부터 되묻는다.

## 금지

- `complete/`는 검색 대상이 아니다. 위치를 짚을 때도 `complete/` 경로를 대지 않는다.
- 다른 `TODO`의 답이 될 만한 코드를 흘리지 않는다.
