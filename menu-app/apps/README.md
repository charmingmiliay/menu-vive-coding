# React 실습 — 앱 다섯 개

3일 동안 앱을 네 개 만들고, 4일차에 다섯 번째 앱을 다룬다.
**앱마다 새 프로젝트**이고, 앞에서 배운 것 위에 하나씩 얹는다.

## 1. 앱 구성과 일정

| 일차 | 앱                  | 구현 예제                   | 시작 방법                       |
| ---- | ------------------- | --------------------------- | ------------------------------- |
| 1    | [`01_react-basics`](01_react-basics/01_GUIDE.md) | 할 일 목록(To-Do List)      | **빈 폴더(from Scratch)** |
| 2    | [`02_api-viewer`](02_api-viewer/02_GUIDE.md)   | GitHub 이모지 뷰어          | 준비된`starter/`폴더          |
| 2    | [`03_list-detail`](03_list-detail/03_GUIDE.md)  | 포켓몬 도감 (PokeAPI)       | 준비된`starter/`폴더          |
| 3    | [`04_form-auth`](04_form-auth/04_GUIDE.md)    | 게시판 CRUD                 | 준비된`starter/`폴더          |
| 4    | [`05_vibe_design`](05_vibe_design/05_GUIDE.md)  | 포켓몬 도감 (디자인 시스템) | -                               |

각 앱 폴더의 **가이드 파일**(`01_GUIDE.md` 처럼 번호가 붙어 있다)에 실행 방법과 완성 확인 목록이 적혀 있다.
위 표의 앱 이름을 누르면 바로 열린다.
전체 복습 목록과 증상별 색인은 저장소 루트의 `REVIEW.md` 에 있다.

## 2. 실행 방법

**앱 1** 은 프로젝트 만드는 것부터 직접 한다. 자세한 것은 `01_react-basics/01_GUIDE.md` 를 본다.

**앱 2 부터** 는 `starter/` 에서 시작한다.

```bash
cd 02_api-viewer/starter
npm install
npm run dev
```

`npm install` 은 **앱마다 한 번씩** 해야 한다. 앱마다 별개의 프로젝트이기 때문이다.
이미 다른 앱이 떠 있으면 주소가 `5174`, `5175` 로 올라간다. **고장이 아니다.**

## 3. complete 폴더의 용도

앱 1 부터 4 까지는 `complete/` 가 함께 들어 있다. **완성된 코드다.**

**먼저 열어 보지 않기를 권한다.** 직접 만들어 보고 막혔을 때, 그리고 다 만든 뒤에 비교할 때 쓴다.
막혔다고 바로 여는 것보다 아래 순서가 낫다.

1. 화면과 콘솔(F12)에 무엇이 나오는지 먼저 본다
2. 값을 `console.log` 로 찍어 본다
3. 에이전트에게 **답이 아니라 힌트**를 달라고 한다
4. 그래도 안 되면 `complete/` 를 연다

## 4. 사용 버전

React 19.3 / Vite 8.3 / react-router 8.4

## 5. CSS 최소화의 이유

앱 1 부터 4 까지 CSS 는 구조만 보이는 최소한만 들어 있다. 색과 레이아웃은 일부러 넣지 않았다.
**디자인은 4일차 `05_vibe_design` 에서 디자인 시스템으로 따로 다룬다.**
3일 동안은 React 가 어떻게 동작하는지에만 집중한다.

## 6. 앱 5의 위치 — 4일차 자료

앱 3 과 **같은 포켓몬 도감**이다. 일부러 그렇게 잡았다.

- 앱 3 은 React 가 어떻게 동작하는지를 본다. CSS 가 거의 없다.
- 앱 5 는 디자인 시스템과 토큰을 먼저 만들고, 에이전트에게 화면을 그리게 한다.

같은 것을 두 번 만드는 것이 아니라, **다른 것을 배우는 데 같은 소재를 쓰는 것**이다.
3일차까지는 열어 보지 않아도 된다.

## 7. 3일 과정의 목표

이 과정에서 실제로 하게 될 일은 **AI 가 만든 React 코드를 읽고, 무엇이 잘못됐는지 짚어내고,
정확하게 고쳐 달라고 지시하는 것**이다. 그래서 증상과 원인을 짝지어 기억하는 것이 중요하다.

| 증상                               | 어디서 다루나 |
| ---------------------------------- | ------------- |
| 화면이 안 그려진다 / 안 바뀐다     | 앱 1, 앱 4    |
| 데이터가 안 뜬다                   | 앱 2          |
| 주소는 바뀌는데 화면이 그대로다    | 앱 3          |
| 입력이 안 된다 / 폼이 새로고침된다 | 앱 4          |

증상별로 어느 절을 볼지는 `REVIEW.md` 맨 아래 **증상으로 찾기** 표에 정리돼 있다.
