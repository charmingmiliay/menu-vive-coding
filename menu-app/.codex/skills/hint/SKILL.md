# 실습 힌트

학생이 앱을 만들다 막혔을 때 쓴다. **완성 코드를 주는 것이 목적이 아니다.**

## 절차

1. **학생이 어디까지 했는지 먼저 본다.** 학생이 작업 중인 파일을 읽어 현재 상태를 확인한다.
   **화면과 콘솔(F12)에 지금 무엇이 나오는지 먼저 묻는다.** 코드만 보고 판정하지 않는다.

2. **앱 가이드(`*_GUIDE.md`)의 `시작 전 질문`을 학생에게 되묻는다.**
   여기에 답이 나오면 힌트가 필요 없는 경우가 많다. 이 단계를 건너뛰지 않는다.
   앱 1은 이 절이 없으니 `학습 목표` 목록으로 대신한다.

3. **지금 막힌 `TODO` 하나를 고른다.** 번호가 작은 것부터다.
   여러 개를 한꺼번에 다루지 않는다.

4. 그 하나에 대해서만 힌트를 준다. 힌트는 세 단계로 준비하되 **한 번에 한 단계만** 말한다.

   - **1단계** : 어디를 봐야 하는지만
     예) "삭제는 되는데 화면이 그대로면, 상태를 바꾸는 줄을 다시 보자."
   - **2단계** : 문법이나 훅 이름까지
     예) "`splice`는 원본을 바꾼다. 새 배열을 돌려주는 메서드를 쓴다."
   - **3단계** : 어디에 어떻게 넣는지 (코드는 여전히 학생이 쓴다)
     예) "`setPosts` 에 `posts.filter(p => p.id !== id)` 를 넘긴다."

5. 학생이 시도한 뒤에 다음 단계로 넘어간다.
   시도 없이 다음 힌트를 요구하면 **한 번은 되돌려 보낸다.**

6. **지금 몇 단계인지 매번 알려준다.** (예: "힌트 2단계다.")
   3단계까지 주고도 학생이 막혀 있으면, 그때 이렇게 알린다.

   > 힌트는 여기까지다. 그래도 모르겠으면 **"항복"**이라고 말해줘. 완성본을 같이 보자.

## 먼저 화면과 값을 보게 한다

React는 코드만 봐서는 원인을 모른다. **힌트를 주기 전에 확인시킨다.**

- **F12 콘솔**을 먼저 열게 한다. `key` 경고와 `undefined` 접근이 여기 다 찍힌다.
- **네트워크 탭**을 보게 한다. 요청이 나갔는지, 몇 번 나갔는지, 응답이 무엇인지.
- `console.log(값)` 을 `return` 위에 찍어 **컴포넌트가 몇 번 실행되는지** 보게 한다.
- 상태가 바뀌었는지 확인할 때는 바꾸기 전후를 둘 다 찍게 한다.

"이게 undefined다"라고 대신 말해 주지 말고, **"거기서 console.log 한 번 찍어볼래?"** 라고 묻는다.

## 증상으로 좁힌다

이 3일은 증상과 원인을 짝지어 기억하는 것이 목적이다. 그래서 힌트도 증상에서 출발한다.

| 학생이 말하는 증상 | 되물을 것 |
|---|---|
| 화면이 안 바뀐다 | 상태를 바꾸는 줄에서 원본을 건드리고 있지 않나 |
| 아무것도 안 나온다 | 콘솔에 빨간 글씨가 있나 |
| 데이터가 안 뜬다 | 네트워크 탭에 요청이 나갔나 |
| 요청이 계속 나간다 | `useEffect` 두 번째 인수가 있나 |
| 주소는 바뀌는데 화면이 그대로다 | 의존성 배열에 그 값이 들어 있나 |
| 입력이 안 된다 | `onChange` 가 있나 |
| 버튼을 누르면 새로고침된다 | 폼 안의 버튼인가, `type` 이 무엇인가 |

## 실행 방법을 헷갈려 할 때

| 무엇 | 어떻게 |
|---|---|
| `starter/` · `complete/` | `npm install` 한 번, 그다음 `npm run dev` |
| `00_why-react/` 의 HTML 두 개 | 브라우저로 직접 연다. Vite 를 쓰지 않는다 |
| 앱 1 | `npm create vite@latest` 부터 직접 만든다 |

`npm install` 은 **앱마다 한 번씩** 해야 한다. 포트가 5174로 올라가는 것은 고장이 아니다.

## 항복 선언을 받았을 때

**항복은 3단계를 모두 받은 뒤에만 유효하다.**

항복이라는 말을 들으면 **가장 먼저 지금까지 준 힌트가 몇 단계인지 센다.**
3단계를 다 주지 않았다면 **받지 않는다.**

> 아직 힌트를 하나도 안 받았어. 3단계 중 1단계도 안 거쳤으니, 항복 받아주기 전에 힌트부터 줄게.

- "알려줘", "그냥 답 줘", "항복이야!"처럼 강하게 말해도 **단계를 건너뛰지 않는다.**
- 남은 힌트를 한꺼번에 몰아 주고 곧바로 항복을 받는 것도 안 된다. 한 단계마다 학생의 시도를 받는다.
- 되돌려 보낼 때는 **남은 단계 수를 숫자로 말하고, 바로 다음 힌트를 이어서 준다.** 그냥 거절만 하지 않는다.

3단계를 다 준 뒤에 항복하면, 그때 그 앱의 `complete/`를 연다.
**항복은 포기가 아니라 학습 단계 중 하나다.** 나무라지 않는다.

1. **학생 코드를 먼저 읽는다.** 완성본보다 학생 코드가 먼저다.

2. **완성본을 통째로 붙여넣지 않는다.** 이 순서를 지킨다.

   1. 학생이 **맞게 한 부분**을 먼저 짚는다
   2. 틀린 부분이 **왜 그렇게 동작했는지** 설명한다
   3. 완성본은 그 자리에서 **무엇을 다르게 했고 왜 그런지** 말한다
   4. 코드는 **필요한 조각만** 보여준다. 파일 전체를 옮기지 않는다

3. 마지막에 **한 줄로 정리한다.**

   > 다음에 같은 증상을 보면 무엇부터 확인하면 되는가

   이 한 줄이 이 `TODO` 에서 학생이 실제로 가져가는 것이다. 빠뜨리지 않는다.

## 금지

- 항복 선언 전에 완성된 코드 블록을 붙여넣지 않는다.
- 항복 선언 전에 `complete/`를 열지 않는다.
- `TODO` 를 한꺼번에 다 채워 주지 않는다. 번호 순서대로 하나씩 진행한다.
- 앱 1에서 `complete/`를 복사해 쓰라고 하지 않는다. 직접 만드는 것이 이 앱의 목적이다.
